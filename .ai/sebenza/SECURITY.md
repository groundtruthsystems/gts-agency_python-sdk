## Threat Register

| ID | STRIDE | Threat | Asset / Boundary | Severity | Likelihood | Status | Mitigation | Source | Updated |
|----|--------|--------|------------------|----------|------------|--------|------------|--------|---------|
| T-001 | Elevation of privilege | Auto-selected governance workflow silently omits the required second-reviewer approval for clinical rule annotations, letting one annotator's work stand with no independent check | Annotation batch governance ↔ clinical rule review workflow | High | Medium | Open | Selection is restricted to published workflows and prefers system ones, with an explicit `workflow_id` override; the server refuses unpublished versions. Residual gap: the workflow list exposes no separation-of-duties flag, so the client cannot filter on it and an org whose only published graph workflow is single-step gets one bound silently | `annotation_workflow_binding_20260822` | 2026-08-22 |
| T-002 | Elevation of privilege | A principal holding workflow-execute but not annotations-write can change which workflow governs an existing batch, since `bind_workflow` is authorized on a different permission from the rest of the annotations surface | Annotation batch ↔ workflow-execute authorization boundary (comand API) | Medium | Low | Open | Server-side only, and narrower than it first appears: `bind_workflow` additionally requires organisation membership (non-members get 404) and accepts only published versions of a workflow matching the batch type. Residual gap: within an org, workflow-execute alone suffices to re-govern a batch the holder could not otherwise administer | `annotation_workflow_binding_20260822` | 2026-08-22 |
| T-003 | Tampering | Re-binding a batch's workflow after some of its jobs are already accepted retroactively changes the review rigour applied to completed clinical rule work | Accepted annotation jobs ↔ workflow governance binding | Medium | Low | Mitigated | Server requires a non-empty written reason whenever the incoming version disables self-approval protection or the job type already has accepted work and jobs would be affected; it rejects a version missing any state the affected jobs occupy, re-checks batch-type compatibility on every rebind, and reports `jobs_regoverned` for audit. The SDK passes `rebind_reason` through rather than inventing one | `annotation_workflow_binding_20260822` | 2026-08-22 |
| T-004 | Information disclosure | Clinical rule graph payloads (up to 50 MiB) cross the agent-to-control-plane boundary without transport encryption enforced by the SDK, exposing guideline content to eavesdropping wherever TLS is not terminated | Agent process ↔ control-plane API (network transport) | Medium | Low | Accepted | TLS is a deployment property; the SDK never downgrades or disables transport security, and local development runs plain HTTP by choice. Accepted rather than mitigated because nothing in the library can enforce it | `annotation_workflow_binding_20260822` | 2026-08-22 |
