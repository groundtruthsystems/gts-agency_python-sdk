| T-008 | Information disclosure | `list_batch_members` returns clinicians' `given_name`, `family_name`, `known_as`, and `email` on the joined read, introducing real people's PII into agent processes that previously had no batch-membership data at all | Batch-membership read (`list_batch_members`) ↔ agent process logs/exports | Medium | Medium | Open | DTO and docstring flag the four display fields as PII (not for casual logging); `examples/quick_annotations.py` prints only presence, never values. | T-010 | Tampering | Opaque `Any`-typed job fields (`annotation_data`, `checklist_state`, `delta`, `vertex_data`, `connected_vertices`, `connected_edges`) pass through the SDK completely unvalidated; a malformed or unexpected shape from either front-end can silently corrupt a consumer's integrity check — observed by the consumer as dropped `part_of` edges publishing while its closure check reported zero problems | Annotation job payload fields (`Any`-typed) ↔ consumer contamination/closure check | Medium | Medium | Accepted | Deliberate: comand does whole-value column replacement and two front-ends write different shapes into the same columns, so a validating model would reject one of them and blind the consumer instead of protecting it. Validation is pushed to the consumer by design; the guideline-agent Publisher added its own payload-shape gate after observing the silent degradation | `annotation_job_reads_20260831` | 2026-09-17 |
| T-004 | Information disclosure | The Keycloak m2m bearer JWT and PHI-capable payloads (clinical rule graphs up to 50 MiB, gateway prompts, OTLP telemetry) cross the agent-to-platform boundary without transport encryption enforced by the SDK, so an on-path attacker can read content and replay the token anywhere TLS is not terminated | Agent process ↔ control-plane API / gateway / OTLP host (network transport) | High | Low | Accepted | TLS is a deployment property; the SDK never downgrades or disables transport security (no `verify=False` path exists), and local development runs plain HTTP by choice (`base_url` defaults to `http://localhost:9003`). Accepted rather than mitigated because nothing in the library can enforce it; short-lived, auto-refreshed token limits replay window | `annotation_workflow_binding_20260822`, `observability_tracing_20260617`, `agent_gateway_client_20260706`, `gateway_openai_only_20260707` | 2026-10-12 |
| T-011 | Information disclosure | A spoofed, compromised, or mis-seeded control-plane response to `GET /api/agentgateways` returns an attacker-controlled gateway URL, and the SDK then sends the m2m bearer JWT plus the org's LLM prompts to that host | Control-plane discovery response ↔ discovered gateway host (token destination) | High | Low | Open | Missing control: no `https` requirement or host allowlist/same-domain check on the discovered `production.url`/`test.url` (only emptiness is checked); explicit `gateway_base_url` bypasses discovery. Discovery itself is authenticated and runs over the control-plane connection | `agent_gateway_client_20260706`, `gateway_streaming_openai_20260707` | 2026-10-12 |
| T-012 | Information disclosure | The OTLP/Langfuse host defaults to `base_url` but is overridable via opts/env, so a tampered environment or option redirects the bearer token and telemetry to an attacker-controlled endpoint | OTLP exporter ↔ configured telemetry host (token destination) | High | Low | Open | Missing control: no allowlist or scheme check on `host`/`logs_endpoint`/`traces_endpoint`; mitigated only by the default (same host as `base_url`) and by environment/config integrity being the deployer's responsibility | `observability_tracing_20260617` | 2026-10-12 |
| T-018 | Elevation of privilege | One shared m2m JWT (same credential, no per-audience scoping) is sent to the control plane, the gateway, and the OTLP host, so compromise or logging at any lesser-trusted hop yields full control-plane API access for the token's lifetime | Shared `CredentialsSupplier` token ↔ control plane / gateway / telemetry backends | High | Low | Open | Missing control: audience-restricted or per-service tokens; mitigated only by short token lifetime with auto-refresh (`auth_hooks.py` re-reads the cached token per request, never persists it) | `observability_tracing_20260617`, `agent_gateway_client_20260706`, `gateway_openai_only_20260707` | 2026-10-12 |
| T-006 | Elevation of privilege | comand silently clamps `list_job_transitions`' `size` to 500 (the endpoint's only clamp, and it reports nothing); a caller requesting more gets exactly 500 back, and a "fewer rows than asked for" end-of-page test reads the clamp as the last page, permanently missing any transition — including a `prior_actor_conflict` flag — beyond row 500 | Job-transition ledger (comand) ↔ SDK caller pagination | High | Low | Open | Documented only (docstring, `size` parameter note, `docs/annotations.md` failure-mode table) advising callers to keep `size` ≤ 500 or treat an exact-500 return as suspect rather than end-of-page. | T-015 | Spoofing | A TLS-verification-off (`insecure`, `verify=False`) option on the telemetry export path would let a network attacker impersonate the OTLP endpoint and harvest the bearer token | OTLP exporter ↔ telemetry endpoint (TLS identity) | Medium | Low | Mitigated | The spec allowed an `insecure` option but none is implemented — no `insecure`/`verify` handling exists in `agency_sdk/observability/` or `auth_hooks.py`, so default certificate verification applies. | T-016 | Information disclosure | Long-lived static credentials (explicit `OTEL` Authorization header, Langfuse public/secret key Basic auth) sit in env/process config, and the fallback chain (explicit header > bearer > Basic) lets a static header silently override the rotating bearer, so a leaked value is valid indefinitely | Telemetry auth config ↔ process environment / Langfuse | Medium | Low | Accepted | Rotating bearer is the default path; the static header and Basic key are explicit caller opt-ins sourced from env/secret store, never written to logs by the SDK. | T-017 | Tampering | A compromised or malicious release of `openai` or its transitive dependencies (httpx, pydantic stack, etc.), now a core dependency of every SDK install, executes in every consuming agent process holding the m2m token and PHI | Python supply chain ↔ every SDK consumer process | Medium | Low | Open | Missing control: `openai>=1.0.0` is a lower bound only, with no lockfile, hash pinning, or dependency audit in CI.
